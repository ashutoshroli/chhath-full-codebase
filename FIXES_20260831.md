# Chhath Portal — Fixes Applied (31 Aug 2026)

## Bug fixes

1. **`father_s_name` D1_ERROR on Edit User Save**
   `mgmt/backend/src/tableRegistry.js` — alias key had a stray trailing space
   (`"Father's Name "`) so it never matched the frontend's key, falling
   through to an auto-slugify that produced `father_s_name` instead of the
   real column `fathers_name`. Trailing space removed (also cleaned up
   `'Mobile '` → `'Mobile'` for the same reason, though that one happened to
   slugify correctly by luck).

2. **WhatsApp Group Active/Inactive toggle never sticking, Loan Consent OTP
   verification unreliable, Popup Management toggle, Announcement Priority
   badge, Error Log "reported" status, and dropdown lists (Category/Payment
   Mode/Village) silently empty — all one root cause.**
   D1 stores TEXT-affinity flag columns (`active`, `otp_verified`, `Priority`,
   `reported`, `Announced`, `Is Resell`) as the *string* `'1'`/`'0'`, not a
   real boolean or number. Every place in the code that checked
   `x === true || x === 1 || x === 'true'` never matched that stored string,
   so the flag silently always read as "off" no matter what was saved.
   Added one shared `isTruthyFlag()` helper (`mgmt/frontend/src/flags.js` on
   the frontend; already-correct versions in `announcements.js`/`crud.js`/
   `docxTemplates.js` reused on the backend) and switched every affected
   check to use it: `whatsapp.js`, `loans.js`, `WhatsApp.jsx`,
   `PopupManagement.jsx`, `AnnouncementPortal.jsx`, `ErrorLog.jsx`,
   `useDropdownList.js`.

3. **PDF wouldn't generate a second time in the same page session**
   (`Cannot attach a module that was already attached: "ImageModule"`) —
   including the silent failure of Collection-Save → auto-PDF → WhatsApp
   link, since that reuses the same code path.
   `mgmt/frontend/src/docxFill.js` created the Docxtemplater `ImageModule`
   **once at module load** and reused that single instance for every render.
   Docxtemplater refuses to attach the same module instance twice. Fixed by
   creating a fresh `ImageModule` instance inside `renderFromZip()` on every
   call.

4. **Resell / Samaan / Kaam entries showing "Rs. 0" in the yearly Report PDF**
   `mgmt/frontend/src/views/PdfExport.jsx` always read `Amount` for every
   contributor row, but Samaan (Material) / Kaam (Service) entries never
   carry a money Amount — the item/work name lives in `Detail` instead — and
   Resell entries have no linked contributor. The report now shows the
   Detail-based label for both cases instead of a bare 0.

5. **Export PDF page — no list of already-generated reports for a year**
   The backend endpoint `getGeneratedFilesForYear` already existed but was
   never called from the frontend. `PdfExport.jsx` now shows an
   "Already Generated — Year X" list under the generator, with download
   links, refreshed automatically after each new generation.

6. **`GENERATED_AT` timestamp missing from some generated docx/PDFs**
   Three of the seven doc-generation call sites forgot to pass
   `GENERATED_AT` into the placeholder data: `DownloadCenter.jsx` (Download
   Center's own Generate button), `ConsentPage.jsx` (the public
   accept/decline consent PDF), and `BulkGeneratePdfs.jsx` (bulk generation).
   All three now inject it the same way the other four paths already did.

7. **Docx template placeholder instructions were incomplete**
   `DocxTemplates.jsx`'s "available placeholders" hints, checked against what
   each generator actually supplies:
   - Receipt: was missing `YEAR`
   - Certificate: was missing `DESIGNATION`
   - Consent (Loaner/Guarantor): was missing `FINAL_REPAYMENT_DAY_NAME`,
     `ACCEPTED_COUNT`/`PENDING_COUNT`/`DECLINED_COUNT`, and all six
     Diwali/Nahay-Khay/Chhath-Arghya date+day-name fields; Guarantor was also
     missing `LOAN_CONSENT_ID`
   - Report — Hindi: was listing the English field names (`NAME`,
     `FATHER_NAME`, `LOAN_TAKER`...) instead of the `_HI` variants a
     Hindi-only template actually needs
   All instruction lists now match what the backend actually generates —
   worth re-checking your existing uploaded .docx templates against the
   updated "Available Placeholders" panel in case any of the newly-listed
   fields would be useful additions.

## New features built

8. **Popup on the Public portal**
   - `PopupManagement.jsx`: added a 4th role option, **"Public"**, alongside
     Superadmin/Admin/Subadmin — tag a popup "Public" to have it show on the
     transparency portal.
   - `Public/backend/src/index.js`: new `action=activePopups` endpoint,
     scoped to **only** the `popups` and `popup_slides` tables (bound
     read-only via a new `DB_MISC` binding in `Public/backend/wrangler.toml`
     — see deploy step below).
   - `Public/frontend`: fetches and shows the popup on every page load/
     refresh (no dismissal memory — matches the requirement that it should
     reappear each time), with swipeable slides if a popup has more than one.

9. **Public API — data minimization**
   Verified the Public worker already only touches the 4 DBs / 8 tables it
   needs (no wider exposure). Additionally trimmed `Email` and `WhatsApp`
   number out of the public `users` payload — neither is ever displayed on
   the public site (`Mobile` is, for Committee listings, so that one stays).

## Deploy / setup steps

### 1. `mgmt-worker` (backend)
No schema changes needed — `fathers_name`, `otp_verified`, `active`, etc.
already exist in your live D1 databases exactly as before; only the *code*
that reads/writes them changed.
```
cd mgmt/backend
wrangler deploy
```

### 2. `mgmt-frontend`
```
cd mgmt/frontend
npm install
npm run build
vercel --prod    # or your existing deploy command
```

### 3. `Public/backend` (chhath-public-api)
**New D1 binding required** — `wrangler.toml` now includes a `DB_MISC`
binding (id `a9298585-e108-4f7e-b555-7da7fc0a1921`, same DB mgmt-worker
already uses). If your Cloudflare account needs this binding provisioned
manually instead of via the committed `wrangler.toml`, add it in the
dashboard: Workers → chhath-public-api → Settings → Bindings → D1 Database →
binding name `DB_MISC` → database `chhath-misc`.
```
cd Public/backend
wrangler deploy
```

### 4. `Public/frontend`
No env vars/build step (per `FRONTEND_DIFF_NOTES.md`) — just re-upload
`index.html`, `script.js`, `style.css` to wherever this is hosted. Double
check the `BASE_API_URL` in `script.js`'s `init()` still points at your real
deployed `chhath-public-api` Worker URL.

### 5. After deploying — quick manual test checklist
- [ ] Edit a User's Father's Name and Save — no more `D1_ERROR`
- [ ] Toggle a WhatsApp Group Active/Inactive twice — badge should flip both ways and stay flipped after refresh
- [ ] Generate a Receipt/Certificate PDF twice in a row without reloading the page — second one should succeed
- [ ] Open Export PDF, pick a year that already has reports generated — list should show them
- [ ] Save a new Collection — WhatsApp message should carry the PDF link
- [ ] Go to Popup Management, create a popup tagged "Public", set it Active — refresh the public portal, popup should appear
- [ ] Loan consent link — verify OTP once, confirm Accept/Decline actually goes through
