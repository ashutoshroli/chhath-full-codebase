# Three targeted PWA/Lighthouse fixes for the v6 public frontend

Three low-risk, audited changes to `Public/frontend-v6` to lift the live site's PWABuilder/Lighthouse scores: the CSP now permits the Cloudflare Web Analytics beacon (clearing a real console error and Best-Practices penalty), the default `premium` skin's home route gains the single semantic `<h1>` it was missing (`h1Count:0` in the audit), and the social preview metadata is strengthened — a fuller `og:title`/`twitter:title` on the home route, a real `1280x720` share image in place of the square app icon, and a matching `summary_large_image` card. i18n gains a `social_title` key in both languages, and both affected test files are updated. The change is frontend-only, public-only, adds no dependencies, leaves the generated manifest byte-identical, and touches only two CSP directives.

Watch for: the `a11y` heuristic change removes DecadeBanner as an h1-provider — validated (confirmed) that every Decade page carries its own h1, so this tightens the check rather than hiding a regression. No blocking concerns.

**Verdict**: APPROVED

## High-level view

The CSP change is additive and surgical: exactly one host added to `script-src` and one to `connect-src`, every other directive byte-identical, still a single valid string, no stray non-schema keys in `vercel.json`. This is the tightest way to unblock the analytics beacon.

The missing home `h1` is fixed by matching the pattern the other four skins already use — a visually-hidden `sr-only` heading rendered on both the failed and ready branches of premium's Home, so heading navigation and the SEO crawler always find one, with no visual change.

The social metadata now diverges from the document title only on the home route: `og:title`/`twitter:title` there use a new descriptive `social_title` ("Chhath Puja Transparency Portal — Navyuvak Chhath Puja Samiti") instead of the bare "Chhath Puja", while inner routes keep their existing `${pageTitle} — ${app_title}`. The share image switches to the existing `screenshots/wide.png` (`1280x720`, already shipped in the manifest) and `twitter:card` is upgraded to `summary_large_image` in `app.html`, which remains the single source of truth for that tag.

The `a11y` test change drops a DecadeBanner clause from the per-skin "exactly one h1" heuristic. DecadeBanner renders no heading and is used only by premium's home, which now has its own `h1`; every Decade page provides its own h1 independently. Removing the clause makes the check stricter, and it still passes.

### CSP: two hosts added, everything else frozen

The only edit to `vercel.json` is `https://static.cloudflareinsights.com` appended to `script-src` and `https://cloudflareinsights.com` appended to `connect-src`; every other directive is byte-unchanged and it remains one valid semicolon-delimited string. The new test parses `vercel.json` and asserts `.not.toHaveProperty('comment')`, guarding against the schema break a prior `comment` key caused. On the security posture: this widens the allowlist by two specific first-party-analytics hosts and nothing broader — no wildcard, no `unsafe-eval`, no relaxation of `object-src`/`base-uri`/`frame-ancestors`. (confirmed)

### Social metadata guards

`social_title` is added to both the `en` and `hi` blocks of `i18n.ts`, and the new test asserts exactly two `social_title:` definitions — a future language-block edit that drops one will fail rather than silently fall back. The share image switches from `/icons/icon-512.png` to `/screenshots/wide.png`, an existing `1280x720` asset already referenced by the generated `manifest.webmanifest` (so the manifest stays untouched); the new test asserts the file exists on disk, so a rename can't silently produce a 404 social image. `Seo.svelte` emits no `twitter:card` of its own — the only occurrence in that file is inside a comment — so `app.html` stays the single source of truth for the `summary_large_image` card, and the test enforces exactly one card across both files. (confirmed)

### DecadeBanner dropped from the a11y h1 heuristic

```
premium/Home.svelte ── uses ──> DecadeBanner (renders NO <h1>)
                      └─ now also renders its own <h1 class="sr-only">

Decade.svelte (per skin, h1 provider verified):
  aurora   → <h1>{decade_title}</h1>
  classic  → <h1>{decade_title}</h1>
  festival → <h1>{decade_title}</h1>
  premium  → <PageHeading titleKey="decade_title" />   (heuristic still counts PageHeading)
  slate    → <h1>{decade_title}</h1>
```

The test previously treated a page containing `DecadeBanner` as if that component supplied the page's h1. It does not — grep for `<h1` in `DecadeBanner.svelte` returns nothing, and DecadeBanner is imported only by premium's `Home.svelte`. The "missing h1" and "at most one h1" heuristics both drop the DecadeBanner clause and keep the `PageHeading` clause. Because the removal makes the check stricter (a page that had leaned on DecadeBanner for credit would now be flagged), the risk to validate was whether any page actually depends on DecadeBanner for its only heading. It does not: premium's home now carries its own sr-only h1, and all five Decade pages provide their own h1 directly or via `PageHeading`. The full `structure-and-motion.test.ts` and `seo.test.ts` suites pass (78 assertions across the two files), confirming no page is left h1-less under the tightened rule. (confirmed)

### Test coverage

The +9 assertions in `seo.test.ts` read the actual source files and would fail on revert: they check `screenshots/wide.png` is the social image and the square icon is not, that exactly one `summary_large_image` card exists across both files, that `socialTitle`/`social_title` drive the home og/twitter title, that `social_title` is defined in both language blocks, that premium home has exactly one h1 and all five skins have exactly one, and that the CSP contains both Cloudflare hosts while keeping `default-src 'self'`/`object-src 'none'` and no `comment` key.

Not tested: the CSP assertions confirm the two hosts are *present* in the right directives but do not assert the other directives are byte-unchanged (that guarantee rests on the diff, which is clean). Not a gap worth blocking on given the diff is a two-token addition.
