# Clickable, safe, wrapping links in the v6 chat transcript (v1)

The v6 floating chat assistant rendered bot replies as plain `{m.text}` inside a `max-w-[80%] whitespace-pre-wrap` bubble, so URLs from the Render chat endpoint (`data.answer`, untrusted) were not clickable, markdown autolinks `<https://…>` showed literal angle brackets, and long unbroken URLs spilled outside the bubble and panel. The fix adds a dependency-free tokenizer (`src/lib/chat/linkify.ts`) that splits a reply into ordered text/link tokens; the template renders text via `{tok.value}` and links via a real `<a>` — no `{@html}` anywhere — and only `http:`/`https:` URLs (validated through `URL()`) ever become anchors. Bubble and anchor gain `break-words [overflow-wrap:anywhere]` on top of the existing `whitespace-pre-wrap` so long URLs wrap. User messages stay plain text.

Watch for: nothing blocking. The XSS posture is sound (**confirmed**) — no dangerous scheme or attribute-breakout payload can reach an anchor, and Svelte escapes both text and the `href`. One minor correctness nit: the trailing-punctuation trimmer also strips a legitimate trailing `<`/`>` and quotes from bare URLs, which is harmless but slightly over-eager (**possible**). Scope is clean — only `Public/frontend-v6` is touched (**confirmed**).

**Verdict**: APPROVED

## High-level view

The safety model is structural, not sanitization-based: `linkifyTokens` returns typed tokens, and the only path to an anchor is a URL that both matches `^https?://` and parses via `URL()` to an `http:`/`https:` protocol. Everything else — `javascript:`, `data:`, `vbscript:`, `file:`, `mailto:`, relative, protocol-relative, `ftp:` — is emitted as a text token and shown literally. Because the template never uses `{@html}`, Svelte escapes both the text tokens and the `href` attribute value, so there is no way for external content to introduce markup or a second attribute.

Precedence is enforced by alternative order in a single combined regex: markdown `[label](url)` first, then autolink `<url>`, then bare `http(s)://`. The markdown and autolink URL sub-patterns themselves require `https?://`, so a `[label](javascript:…)` never matches the markdown branch and falls through to text. Bare-URL matches get sentence punctuation trimmed off the tail with paren-balancing preserved for Wikipedia-style links.

The overflow fix pairs `break-words` with the stronger `[overflow-wrap:anywhere]` on both the bubble and the anchor while keeping `whitespace-pre-wrap`, which is what actually breaks an unbroken URL string inside `max-w-[80%]`.

Existing behavior is preserved: welcome message, 30s timeout/abort, `role="log"`/`aria-live`/`aria-busy` wiring, and dialog behavior are untouched. The added `open`/`seedMessages` props are a test seam, initialized through `untrack` so they don't create reactive dependencies and default to the prior production behavior.

Tests are real regression guards: the jsdom component test mounts the actual component with a seeded bot message and asserts a clickable wrapping anchor with `target=_blank` + `rel` containing `noopener` and no angle brackets — the orchestrator's mutation probe confirmed reverting the render to `{m.text}` fails it.

### Scheme safety and the no-`{@html}` guarantee

`safeHref` is the single gate: it requires `^https?://` (case-insensitive) and then re-validates via `new URL()` that the parsed protocol is exactly `http:` or `https:`, returning `null` otherwise. Every branch that fails the gate calls `pushText(full)`, so the rejected substring becomes an escaped text token. This covers the required rejections — `javascript:`, `data:`, `vbscript:`, `file:`, `mailto:`, relative, and protocol-relative — and the tests exercise all of them plus `ftp:`.

Mixed-case schemes are handled: the `^https?://` check is case-insensitive and `URL()` normalizes the protocol to lowercase, so `HTTPS://` still lands as `https:`. A `data:`/`javascript:` scheme can never sneak through because it fails the leading `^https?://` guard before `URL()` is even consulted.

The attribute-breakout question resolves structurally. The bare-URL and autolink patterns stop at whitespace, `<`, and `>` (`[^\s<>]+`), so an injected `"><img …>` terminates the URL at the `<` and the remainder is text. Even in the residual case where a valid `https://` URL legitimately contains a quote, it stays inside a single `href` value and Svelte escapes attribute values, so no second attribute can be introduced — the `cannot break out of the href` test pins this, and the component test confirms `javascript:` is never anchored in a live render.

A subtle but correct point: a markdown label carrying HTML, e.g. `[<img onerror=x>](https://ok.com)`, produces `label: "<img onerror=x>"` which renders through `{tok.label}` and is escaped, so the label text is inert.

### Linkify precedence and punctuation handling

The combined `TOKEN_RE` encodes precedence by alternative order (markdown link → autolink → bare URL). Both the markdown and autolink URL sub-patterns hard-require `https?://`, which is why `[click me](javascript:alert(1))` matches nothing and remains literal text — the test confirms zero link tokens. The zero-width-match guard (`if (TOKEN_RE.lastIndex === start) TOKEN_RE.lastIndex++`) prevents an infinite loop, though none of the alternatives can currently match empty.

`trimTrailingPunct` strips sentence punctuation off the tail of a bare URL while keeping a closing paren when parens balance (Wikipedia case). The `TRAILING_PUNCT` set also lists `<`, `>`, `"`, `'` — but the bare-URL regex already excludes `<`/`>` via `[^\s<>]`, so those two entries are effectively unreachable for bare URLs; the quote entries only matter for URLs that genuinely end in a quote character. This is over-broad rather than wrong, and does not affect autolink/markdown URLs (which aren't passed through the trimmer). Newline and indentation preservation is verified directly by the `preserves newlines and leading indentation exactly` test.

### Overflow fix

The bubble keeps `whitespace-pre-wrap` (so newlines and runs of spaces render) and adds `break-words [overflow-wrap:anywhere]`; the anchor carries the same pair. `overflow-wrap: anywhere` is the class that actually forces a break inside a long unbroken URL, which `break-words` alone (equivalent to `overflow-wrap: break-word`) does not always do at the start of a line. The component test asserts a wrap class is present on the anchor or its bubble, guarding against a silent regression of the wrapping fix.

### The test-seam props and the welcome effect

The one non-obvious interaction: `welcomed` is now pre-set true when `seedMessages` is non-empty, so a seeded transcript isn't clobbered by the welcome `$effect`. In production `seedMessages` defaults to `[]`, so `welcomed` starts false and the welcome message still seeds on first open exactly as before. Both props are initialized through `untrack`, so reading them at setup registers no reactive dependency and can't perturb the existing state graph.
